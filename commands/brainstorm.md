# Gemini Brainstorm

Generate creative ideas using Gemini CLI with structured prompting. You MUST follow every step below.

## Input

- Topic: `$ARGUMENTS`

If `$ARGUMENTS` is empty, ask the user what they want to brainstorm about.

## Step 1: Gather Context

Run:
```
sh "${CLAUDE_PLUGIN_ROOT}/scripts/gather-context.sh" .
```

```
sh "${CLAUDE_PLUGIN_ROOT}/scripts/recent-files.sh" . 30
```

Also use Grep to find files related to the topic keywords for additional context.

## Step 2: Determine Domain and Methodology

**Domain** — Infer from the project context and topic:
- If project is Node.js/Python/Rust/Go/Java → `Software Engineering`
- If topic mentions business/revenue/growth/pricing → `Business Strategy`
- If topic mentions design/UX/UI/layout → `Product Design`
- If topic mentions marketing/growth/users → `Growth & Marketing`
- If topic mentions research/experiment/hypothesis → `Research`
- If topic mentions creative/writing/content → `Creative`
- Default → `Software Engineering`

**Methodology** — Choose based on the nature of the topic:
- Improving or modifying something existing → `SCAMPER` (Substitute, Combine, Adapt, Modify, Put to other use, Eliminate, Reverse)
- Solving a user/customer problem → `Design Thinking` (Empathize, Define, Ideate, Prototype, Test)
- Need fundamentally new approaches → `First Principles` (Break down to fundamentals, rebuild from ground truth)
- Looking for unexpected connections → `Lateral Thinking` (Random entry, provocation, analogy)
- General or unclear → `Divergent` (Generate as many ideas as possible without judgment)

## Step 3: Call Gemini via CLI

Write the full prompt to `/tmp/gemini-discuss-prompt.txt` using the Write tool:

```
<system_instructions>
You are an expert consultant specializing in {inferred domain}.
Your task is to conduct a structured brainstorming session using the {chosen methodology} methodology.
Be creative, specific, and grounded in the project's actual context.
</system_instructions>

<context>
{paste gather-context.sh output here}
</context>

<recent_activity>
{paste recent-files.sh output here}
</recent_activity>

<relevant_findings>
{paste any relevant code patterns or files found via Grep}
</relevant_findings>

<task>
Generate exactly 12 distinct ideas for the following topic:
"{$ARGUMENTS}"

Methodology: {chosen methodology}
Domain: {inferred domain}
</task>

<output_format>
For each idea, provide:

### Idea N: {Title}
**Description:** A clear, actionable description of the idea (2-3 sentences).
**Feasibility:** {1-5} | **Impact:** {1-5} | **Innovation:** {1-5}
**Analysis:** Brief feasibility assessment — what makes this easy or hard to implement, key risks, and dependencies.

After all ideas, provide:

## Summary
- **Quick Wins** (High feasibility, High impact): List idea numbers
- **Strategic Bets** (Lower feasibility, High impact): List idea numbers
- **Experimental** (High innovation): List idea numbers
</output_format>
```

Then run via Bash:

```
cat /tmp/gemini-discuss-prompt.txt | gemini -m gemini-3-pro-preview && rm -f /tmp/gemini-discuss-prompt.txt
```

## Step 4: Present Ideas

Display Gemini's brainstorm results. Add a footer:

```
---
*Ideas generated by Gemini (gemini-3-pro-preview). Domain: {domain}, Methodology: {methodology}.*
```

## CRITICAL RULES

1. **ALWAYS** pass `-m gemini-3-pro-preview` to the gemini CLI. Never omit it.
2. Always provide real project context for grounded ideas — never call Gemini without context.
3. Always write the prompt to a temp file and pipe it — never embed large prompts in shell arguments.
4. Clean up the temp file after the call.
5. Choose methodology deliberately based on the topic nature, not randomly.
